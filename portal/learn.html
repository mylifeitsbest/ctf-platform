Что такое Attack-Defense

Коротко и с нуля: чем это отличается от тасков, которые вы решали.

В обычном CTF (Task-Based) есть задача — вы её решаете, сдаёте флаг, всё. В Attack-Defense всё одновременно: у каждой команды работает одинаковый набор сервисов (маленьких программ-сайтов), и игра идёт раундами.

🗡 Атака

Ты находишь дыру в сервисе соперника, достаёшь из него секрет (флаг) и сдаёшь его — за это очки.

🛡 Защита

Та же дыра есть и у тебя. Надо её закрыть (запатчить), но так, чтобы сервис продолжал работать.
Главная мысль
Нельзя просто выключить сервис, чтобы не украли. Если он не работает — штраф (это называется SLA). Задача: закрыть дыру и оставить сервис живым.

Весь остальной курс — это по сути два навыка, доведённые до автоматизма: быстро находить и забирать чужие флаги и быстро чинить свои дыры. Плюс автоматизация, чтобы не делать это руками.

Слова, которые все кидают

Ферма, сплойт, чекер, тик… Разберём, чтобы ты не кивал молча.

флаг
Строка-секрет, которую надо украсть. У нас выглядит так: 2GSEP3JOB2SFRG2XRG0DH11878YL11C=
сервис
Маленькая программа-сайт с дырой. Их несколько, у каждой команды свои.
эксплойт / сплойт
Скрипт, который использует дыру и достаёт флаг. «Написать сплойт» = написать такой скрипт (обычно на Python).
чекер
Судья. Каждый раунд кладёт свежие флаги в сервисы и проверяет, что они живые (это и есть SLA).
раунд / тик
Один цикл игры (напр. 60 сек). Каждый тик — новые флаги. Старые «протухают».
SLA
Оценка «жив ли твой сервис». Сломал при патче — теряешь очки, даже если тебя не взломали.
сабмиттер
Точка, куда сдают украденные флаги, чтобы получить очки.
ферма
Скрипт, который сам гоняет твои сплойты по ВСЕМ соперникам каждый тик и сам сдаёт флаги. Без неё не успеть руками.
replay / кража трафика
Соперник атакует тебя → его запрос виден в твоём трафике → ты повторяешь его по всем. Чужой труд = твои очки.
вулнбокс
Твоя машина с сервисами, которую ты защищаешь.

урок 1 · IDOR

Дыра №1 — «дай чужое по номеру»

Сервис notes хранит заметки. Флаг лежит в чужой приватной заметке. Задача — прочитать её без пароля.

Шаг 1. Пощупай дыру руками

Сервис отдаёт заметку по её номеру — GET /note/1 — и не проверяет, твоя ли она. Это называется IDOR (небезопасная ссылка на объект). Меняй номер и смотри. Пароль мы не вводим.

notes · team2 (чужой)
GET http://team2/note/
нажми «Запросить»…
Увидел?
По номерам 1, 3, 5 вылезают чужие флаги. Ты только что совершил атаку — руками. Теперь автоматизируем.

Шаг 2. Напиши эксплойт

Эксплойт — это тот же перебор, но кодом. Ниже почти готовый скрипт на Python. Впиши диапазон перебора вместо ??? (попробуй range(1, 200)) и нажми «Проверить».

notes_sploit.py

Шаг 3. Запатчи у себя

Теперь ты — защита. Дыра в том, что /note/<id> не проверяет владельца. Нажми, чтобы применить патч (добавить проверку «а заметка его?»), и снова попробуй перебор — чужое больше не отдаётся, а своё и SLA работают.

@app.get("/note/<int:nid>")
def get_note(nid):
    n = NOTES.get(nid)
    if not n: return error(404)
    # дыры: любой может прочитать любую заметку
    return jsonify(body=n["body"])

урок 4 · скрипты

Ферма — делает всё за тебя

Руками сдавать флаги = проиграть. Ферма берёт твои сплойты и каждый тик бьёт ими по всем соперникам, собирает флаги и сдаёт их. Это и есть «автоматизация», которой вы боялись.

Ферма — это просто цикл. Разбери построчно:

sploits = load_sploits()           # все твои *_sploit.py
while True:                         # каждый тик
    flags = set()
    for team in teams:             # по каждому сопернику
        for svc, exploit in sploits:
            flags |= set(exploit(team))   # запускаем сплойт
    submit(flags)                  # сдаём пачкой в сабмиттер
    sleep(tick)

Нажми — ферма прогонит твои 3 сплойта по 3 соперникам (симуляция):

farm.py
готова к запуску…
очки атаки: 0
Вывод
Один человек в команде отвечает за ферму. Пока остальные ищут новые дыры — ферма доит старые 24/7.
